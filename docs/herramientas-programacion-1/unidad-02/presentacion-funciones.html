01

El problema del bloque repetido

¿Qué pasa cuando el mismo cálculo vive en cinco lugares y la regla cambia?

El caso

Dos totales, el mismo bloque

double[] precios = { 4599.90, 12999.00, 8500.50, 2300.00, 15750.75 };

double totalOriginal = 0;
for (int i = 0; i < precios.Length; i++)
{
    totalOriginal += precios[i];
}
Console.WriteLine($"Total antes del descuento: {totalOriginal}");

double descuento = 0.10;
double totalConDescuento = 0;
for (int i = 0; i < precios.Length; i++)
{
    totalConDescuento += precios[i] * (1 - descuento);
}
Console.WriteLine($"Total con descuento: {totalConDescuento:F2}");

El inventario guarda cinco precios. El programa calcula el total antes y después de aplicar un descuento del 10 %.

Total antes del descuento: 44150,15
Total con descuento: 39735,14
Compara los dos for: solo cambia la línea del medio. El resto es el mismo bloque, copiado.

En los 5 lugares. Y el compilador no avisa de un olvido: el programa compila, corre y muestra un total distinto en el lugar que quedó sin editar. Compruébalo en la siguiente diapositiva.

Profundiza

Una receta, y cuándo no hace falta

Una recetaSe escribe una vez y se usa cada día
La receta de arepas está escrita una sola vez. Cada día la sigues con cantidades distintas y no la copias de nuevo. La receta es la función; cocinar es la llamada.
Reescribir la receta en cada cocina. Si cambias la sal en una, las demás siguen con la receta vieja.
Un formulario con campos en blancoImpreso una vez, lleno cada vez
El formulario se imprime una vez. Cada persona lo llena con sus datos. El formulario es la función, los campos en blanco son las entradas y cada formulario lleno es una llamada.
Cuándo no hace faltaUn bloque que aparece una sola vez
Si el programa suma los precios una sola vez y no volverá a hacerlo, un for suelto basta: no hay repetición que evitar. Una función por cada línea suelta llena el programa de saltos y cuesta más leerlo.
La segunda vez que vas a copiar un bloque, conviértelo en función.

¿Cómo se escribe una función y cómo le llega lo que necesita para trabajar?

Anatomía

La firma es el contrato

static double CalcularTotal(double[] precios)
{

    for (int i = 0; i < precios.Length; i++)

El cuerpo es lo que va entre las llaves de la función. Cada variable que declaras ahí es local: existe mientras la función corre y desaparece al terminar. Lo que queda fuera de las llaves es de Main, el punto desde donde el programa llama a las funciones.

Profundiza

Tres piezas de la firma, con calma

staticLa función recibe sus datos por parámetros
Las funciones de este curso llevan static. Es una función suelta: no depende de un objeto ni de las variables sueltas del programa.
Leer dentro de la función una variable declarada afuera, como impuesto. El compilador responde CS8421: Una función local estática no puede contener una referencia a "impuesto". Pásala como parámetro.
Tipo de retornoLo que sale tiene un tipo fijo
El tipo de retorno va justo antes del nombre. Es cualquier tipo que ya conoces (double, int, string, bool, un vector) o void si la función no devuelve nada.
La etiqueta de un frasco: antes de abrirlo ya sabes qué contiene.
Nombres en PascalCaseLas funciones empiezan en mayúscula
Cada palabra del nombre lleva mayúscula inicial: CalcularTotalConDescuento. Un buen nombre empieza con un verbo y dice qué hace la función.
Usar nombres vagos como Calcular o Proceso: obligan a abrir el cuerpo para entender qué hacen.

El problema de la salida

Dos funciones, dos tipos de salida

CalcularTotal

Calcula y entrega 44150,15. El programa lo recibe y puede guardarlo, compararlo o usarlo en otro cálculo.

Predice antes de ejecutar

Tres vectores, tres llamadas

    {

    }
    return true;
}

Cada Console.WriteLine imprime lo que devuelve la función. ¿Qué salida produce el programa, en orden?

En b el return de adentro del if corta la función en el -50.0 y nunca mira el último precio. En c el vector vacío no entra al foreach: ningún precio es negativo y se llega al return true; final.

Práctica

Reto 1: refactoriza

Reemplaza los dos bloques por una función Maximo que reciba un vector double[] y devuelva su mayor valor.

Prueba simulada en JavaScript. No compila C#. Revisa sintaxis y tipos y prueba varios vectores; si algo no se traduce, solo revisa la forma.

PistaPor dónde empezar
Empieza con static double Maximo(double[] valores). Dentro, guarda valores[0] en una variable, recorre el resto con un for y cierra con return de esa variable.
SoluciónÁbrela cuando lo hayas intentado 
static double Maximo(double[] valores)
{
    double mayor = valores[0];
    for (int i = 1; i < valores.Length; i++)
    {
        if (valores[i] > mayor) mayor = valores[i];
    }
    return mayor;
}
