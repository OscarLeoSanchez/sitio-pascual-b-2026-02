1 Lo que vas a lograr

En la Semana 1 dejaste HolaPascual ejecutando y publicado en GitHub. Esta semana abres ese mismo tipo de proyecto y aprendes de qué está hecho por dentro: cómo se organiza un programa de C#, qué tipos de datos existen para representar la información y cómo entra y sale esa información por la consola.

Objetivos concretos:

  1. Explicar la estructura de un archivo Program.cs con sentencias de nivel superior.
  2. Aplicar la sintaxis básica del lenguaje: sentencias, bloques, comentarios y convenciones de nombres.
  3. Elegir el tipo de variable correcto según el dato que representa: enteros, reales, texto, caracteres y valores lógicos.
  4. Leer datos por consola y convertir el texto que devuelve Console.ReadLine al tipo que necesitas, sin que un dato inválido detenga el programa.

Console.OutputEncoding = System.Text.Encoding.UTF8;

2 Anatomía de un programa con sentencias de nivel superior

Desde dotnet new console, el Program.cs que generó el SDK no tiene una clase Program ni un método Main visibles. Eso no significa que no existan: el compilador los genera por ti a partir de lo que escribes. A este estilo se le llama sentencias de nivel superior (top-level statements), y es la forma recomendada para escribir programas nuevos en C#.

Un archivo con sentencias de nivel superior se organiza en tres bloques, en este orden:

  1. Directivas using, si necesitas una biblioteca que no está entre las que .NET importa de forma implícita (ImplicitUsings en el .csproj, que ya viste en la Semana 1).
  2. Las sentencias de nivel superior, que son el cuerpo real de tu programa. Van directamente en la raíz del archivo, sin envolverlas en una clase ni en un método.
  3. Definiciones de tipos, si el archivo también declara una clase o un struct. Deben ir después de las sentencias de nivel superior, nunca antes.

Solo puede haber un archivo del proyecto con sentencias de nivel superior. Cuando el proyecto crezca y necesites varias clases en archivos separados (a partir de la Unidad 3), esos archivos adicionales no llevan sentencias de nivel superior: solo definiciones de tipos.

NotaQué genera el compilador por dentro

El compilador convierte tus sentencias de nivel superior en un método Main real. La firma exacta depende de si usas return o await en el cuerpo:

Tu código usa Firma que genera el compilador
Ni return ni await static void Main(string[] args)
Solo return static int Main(string[] args)
Solo await static async Task Main(string[] args)
return y await static async Task<int> Main(string[] args)

No necesitas escribir esa firma. La vas a reconocer cuando en la Unidad 3 vuelvas a un Main explícito para organizar un proyecto más grande.

También tienes disponible la variable args, con los argumentos que reciba tu programa desde la línea de comandos. Nunca es null: si no pasaste ninguno, args.Length vale cero.

3 Sintaxis básica del lenguaje

C# comparte varias reglas con el pseudocódigo que ya escribiste en Fundamentos de Programación, más un conjunto de símbolos que el compilador exige de forma estricta.

Regla En C#
Fin de sentencia Punto y coma ; al final de cada instrucción
Bloque de código Llaves { }. Todo lo que agrupas (el cuerpo de una función, de un if, de un ciclo) va entre ellas
Comentario de una línea // texto, desde ahí hasta el final del renglón
Comentario de varias líneas /* texto */, puede abarcar varios renglones
Mayúsculas y minúsculas El lenguaje distingue: precio y Precio son variables distintas
Espacios e indentación No afectan la ejecución, pero sí la lectura. Este curso indenta con 4 espacios 
// Esto es un comentario de una linea.
int cantidad = 5;   // el punto y coma cierra la sentencia

/* Esto es un comentario
   de varias lineas. */
if (cantidad > 0)
{
    Console.WriteLine("Hay existencias.");
}

Olvidar el punto y coma o dejar una llave sin cerrar es, con diferencia, el error más común de las primeras semanas. El compilador señala la línea siguiente a la del error real, así que si un mensaje no tiene sentido, revisa primero la línea de arriba.

Convenciones de nombres

C# no obliga un estilo de nombres, pero la comunidad y Microsoft usan uno consistente que este curso sigue desde ya:

Elemento Convención Ejemplo
Variables y parámetros camelCase: primera palabra en minúscula, las siguientes con inicial mayúscula precioUnitario, nombreProducto
Clases, métodos y tipos propios PascalCase: todas las palabras con inicial mayúscula Producto, CalcularTotal
Constantes PascalCase también, en este curso StockMinimo

Un nombre de variable debe decir qué representa. cantidad comunica más que c, y cantidadEnInventario más que cantidad cuando el programa maneja varias cantidades a la vez.

4 Tipos de variables

Cada variable en C# tiene un tipo fijo, decidido cuando la declaras. El compilador impide mezclar tipos incompatibles antes de que el programa llegue a ejecutarse: es lo que se llama tipado fuerte, y es una de las diferencias más notorias frente al pseudocódigo de Fundamentos de Programación.

int a = 5;
bool esValido = true;

int total = a + 2;        // correcto
// int error = a + esValido;   // el compilador lo rechaza: no se puede sumar int y bool

Tipos por valor y tipos por referencia

Todos los tipos de C# caen en una de dos categorías, y la diferencia importa desde ya porque determina qué pasa cuando copias una variable en otra.

  • Tipos por valor: int, double, bool, char y los demás tipos numéricos. La variable guarda el dato directamente. Copiarla crea una copia independiente.
  • Tipos por referencia: string, los arreglos (Semana 6) y las clases que definas desde la Unidad 3. La variable guarda una dirección hacia el dato real, que vive aparte. Copiar la variable copia la dirección, no el contenido: las dos variables terminan apuntando al mismo dato.

Por ahora vas a trabajar sobre todo con tipos por valor y con string. La diferencia se vuelve crítica más adelante, cuando pases arreglos y objetos como parámetros de una función.

Tipos numéricos: cuál usar y cuándo

C# tiene varios tipos numéricos, cada uno con un tamaño y un propósito distinto.

Para este curso, la regla práctica es corta:

  • Cuenta cosas con int. Es el tipo entero por omisión y alcanza para prácticamente cualquier cantidad que vayas a manejar en los ejercicios del semestre.
  • Mide cosas con double. Es el tipo real por omisión: precios, promedios, medidas.
  • Vas a conocer decimal en esta semana porque explica un comportamiento de double que necesitas entender antes de calcular con dinero, aunque en este curso sigas usando double para mantener la sintaxis simple.
double resultado = 0.1 + 0.2;
Console.WriteLine(resultado);

decimal resultadoExacto = 0.1m + 0.2m;
Console.WriteLine(resultadoExacto);
0.30000000000000004
0.3

double no representa exactamente todas las fracciones decimales, porque internamente guarda el número en base binaria. Para la mayoría de los cálculos del curso esa diferencia no se nota. Cuando trabajes con dinero de verdad, fuera de este curso, ese es el motivo por el que se usa decimal.

Caracteres, texto y valores lógicos

Tipo Guarda Ejemplo Nota
char Un solo carácter, entre comillas simples char inicial = 'P'; Es un tipo por valor, aunque parezca texto
string Texto de cualquier longitud, entre comillas dobles string nombre = "Cable HDMI"; Es un tipo por referencia
bool true o false, nada más bool activo = true; Resultado natural de una comparación

var y el tipo explícito

var le pide al compilador que infiera el tipo a partir del valor que asignas. El tipo queda igual de fijo que si lo hubieras escrito tú: var no crea una variable de tipo flexible.

var cantidad = 12;        // el compilador fija el tipo en int
var precio = 4599.90;     // el compilador fija el tipo en double

Este curso usa el tipo explícito (int cantidad = 12;) en el material, porque para quien empieza es más fácil verificar que declaró el tipo que quería. Usa var cuando el tipo ya es obvio por el lado derecho de la asignación; en cualquier otro caso, prefiere escribirlo.

Valores por defecto

Toda variable de tipo por valor tiene un valor por defecto si la inicializas con la palabra clave default en lugar de un literal:

int contador = default;
double total = default;
bool encontrado = default;

Console.WriteLine($"contador: {contador}, total: {total}, encontrado: {encontrado}");
contador: 0, total: 0, encontrado: False

El compilador exige que toda variable local tenga un valor antes de leerla. default es útil cuando el valor inicial no importa porque lo vas a sobrescribir enseguida, por ejemplo antes de convertir un dato leído por consola, como haces en la sección siguiente.

5 Entrada y salida por consola

Ya usaste Console.WriteLine, Console.Write y Console.ReadLine en la Semana 1. Esta semana los usas con intención: para construir un pequeño registro de datos.

El punto que hay que fijar es este: Console.ReadLine siempre devuelve string, sin importar qué le pidas al usuario que escriba. Si necesitas un número, tienes que convertir ese texto tú mismo antes de poder operar con él.

Console.Write("Cantidad: ");
string? texto = Console.ReadLine();

// texto es "12", una cadena. Todavia no es un numero.
// int total = texto + 3;   // el compilador lo rechaza

Qué significa el signo de interrogación en string?

Console.ReadLine puede devolver null si la entrada estándar se cierra, por ejemplo cuando el programa corre sin una consola interactiva detrás. C# rastrea esa posibilidad con los tipos de referencia que admiten valores nulos: string? dice “esta variable puede contener un string o puede contener null”. Un string sin el ? es una promesa al compilador de que la variable nunca va a ser null; si igual llega a serlo, el compilador te avisa con una advertencia.

Este curso usa string? en todo lo que venga directo de Console.ReadLine, y resuelve el posible null de una de estas dos formas:

  • ?? (coalescencia nula). Console.ReadLine() ?? "" usa la cadena vacía si el resultado fue null.
  • ! (perdón nulo, null-forgiving). texto! le dice al compilador “confía en mí, aquí no va a ser null”. No hace ninguna comprobación real: úsalo solo cuando estás seguro, porque si te equivocas el programa falla al ejecutarse en vez de avisarte al compilar.

6 Conversión de tipos: Convert, Parse y TryParse

C# ofrece varias formas de convertir un string a un tipo numérico. No son intercambiables: se diferencian en qué hacen cuando el texto no es un número válido.

Forma Si el texto no es válido Cuándo usarla
Convert.ToInt32(texto) Lanza una excepción (FormatException, o ArgumentNullException si el texto es null) Casi nunca en este curso: mezcla mal el manejo de null con el de texto inválido
int.Parse(texto) Lanza FormatException y detiene el programa si no atrapas el error Cuando ya validaste el texto por otro medio y confías en que es válido
int.TryParse(texto, out int valor) Devuelve false y valor queda en 0. No lanza ninguna excepción La opción por omisión para leer datos del usuario

Compruébalo con Parse, sin protegerlo:

Console.Write("Precio unitario: ");
string? texto = Console.ReadLine();
double precio = double.Parse(texto!);
Console.WriteLine($"Precio registrado: {precio}");

Si el usuario escribe algo que no es un número, el programa se detiene con un error sin manejar:

Precio unitario: abc
Unhandled exception. System.FormatException: The input string 'abc' was not in a correct format.
   at System.Number.ThrowFormatException[TChar](ReadOnlySpan`1 value)
   at System.Double.Parse(String s)
   at Program.<Main>$(String[] args) in ...\Program.cs:line 18

TryParse evita ese desenlace. Intenta la conversión y te dice si funcionó con un valor lógico, en vez de interrumpir el programa:

Console.Write("Cantidad en inventario: ");
string? texto = Console.ReadLine();

if (int.TryParse(texto, out int cantidad))
{
    Console.WriteLine($"Cantidad valida: {cantidad}");
}
else
{
    Console.WriteLine($"'{texto}' no es un numero entero valido.");
}

out int cantidad declara la variable de salida en el mismo lugar donde la usas. Dentro del bloque if, cantidad ya tiene el valor convertido y disponible.

Desde esta semana, usa TryParse para todo dato que venga del teclado. Vas a usar Parse y Convert en contadas ocasiones, cuando el dato venga de una fuente que ya validaste antes.

7 Caso de uso: el primer registro del sistema de gestión

El proyecto que vas a construir durante el semestre es un sistema de gestión: la semana 5 le suma decisiones y ciclos, la 10 arreglos y funciones, y la 16 lo reescribe con clases e interfaz gráfica. Esta semana sientas la base: representar los datos de un producto con las variables correctas y leerlos de forma segura por consola.

// Herramientas de Programacion I - Semana 02
// Registro de un producto para el futuro sistema de gestion de inventario.

Console.WriteLine("Sistema de gestion - Registro de producto");
Console.WriteLine("==========================================");
Console.WriteLine();

Console.Write("Nombre del producto: ");
string nombre = Console.ReadLine() ?? "";

Console.Write("Precio unitario: ");
string? textoPrecio = Console.ReadLine();
bool precioValido = double.TryParse(textoPrecio, out double precio);

Console.Write("Cantidad en inventario: ");
string? textoCantidad = Console.ReadLine();
bool cantidadValida = int.TryParse(textoCantidad, out int cantidad);

Console.WriteLine();

if (!precioValido || !cantidadValida)
{
    Console.WriteLine("No se pudo registrar el producto: revisa el precio y la cantidad.");
}
else
{
    double valorTotal = precio * cantidad;

    Console.WriteLine("Resumen del producto");
    Console.WriteLine("---------------------");
    Console.WriteLine($"Nombre     : {nombre}");
    Console.WriteLine($"Precio     : {precio}");
    Console.WriteLine($"Cantidad   : {cantidad}");
    Console.WriteLine($"Valor total: {valorTotal}");
}

Una corrida con datos válidos:

Sistema de gestion - Registro de producto
==========================================

Nombre del producto: Cable HDMI 2 metros
Precio unitario: 4599.90
Cantidad en inventario: 12

Resumen del producto
---------------------
Nombre     : Cable HDMI 2 metros
Precio     : 4599.9
Cantidad   : 12
Valor total: 55198.799999999996

Dos detalles reales de esta salida, no simplificados a propósito:

  • Precio imprime 4599.9, sin el cero final que escribiste. double no guarda ceros decorativos: guarda el número.
  • Valor total imprime 55198.799999999996 en vez de 55198.8. Es la misma imprecisión de double que viste en la sección de tipos numéricos, ahora aplicada a un cálculo real. No es un error del programa: es el comportamiento documentado del tipo.

Una corrida con un dato inválido, sin que el programa se caiga:

Sistema de gestion - Registro de producto
==========================================

Nombre del producto: Mouse inalambrico
Precio unitario: abc
Cantidad en inventario: 5

No se pudo registrar el producto: revisa el precio y la cantidad.

TryParse dejó precioValido en false y el programa siguió corriendo hasta el final, sin lanzar ninguna excepción.

8 Errores frecuentes

Error 1

FormatException al leer un número

Causa. Usaste Parse o Convert.ToInt32 sobre un texto que no es un número válido, y nadie protegió esa conversión.

Solución. Cambia a TryParse y decide qué hacer en la rama false, en vez de dejar que el programa se detenga con una excepción sin manejar.

Error 2

El compilador rechaza una operación entre tipos

Causa. Intentaste sumar o comparar valores de tipos incompatibles, por ejemplo un string con un int sin convertir, o un int con un bool.

Solución. Revisa el tipo de cada variable involucrada. El tipado fuerte de C# no permite las conversiones implícitas que sí acepta el pseudocódigo de Fundamentos de Programación.

Error 3

El texto que pide el dato queda pegado a la respuesta

Causa. Usaste Console.WriteLine en vez de Console.Write para el mensaje que precede a un Console.ReadLine. WriteLine salta de línea antes de que el usuario escriba, y el mensaje queda separado de la respuesta.

Solución. Usa Console.Write (sin Line) cuando el siguiente paso es leer una respuesta en la misma línea.
