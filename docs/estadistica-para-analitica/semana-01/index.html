Abrir la presentación de la sesión

1 De qué va esta semana

Esta semana no tiene entregable ni nota. Hace tres cosas: te muestra cómo está armado el módulo, deja el entorno de Python instalado y verificado, y pone sobre la mesa el problema que la estadística existe para resolver.

Al cerrar la guía deberías poder:

  1. Ubicar cada unidad del módulo dentro del ciclo de resolución de un problema con datos.
  2. Ejecutar Python en un entorno virtual con las siete librerías del semestre.
  3. Decir qué aporta cada librería y por qué están todas.
  4. Explicar por qué una medición repetida no devuelve el mismo número, y qué consecuencia tiene eso para una decisión.

2 La estadística como proceso de decisión

Resolver un problema con datos toma cuatro pasos:

  • Formular la pregunta. Qué se quiere saber, sobre qué proceso, y en qué términos medibles se deja plantear.
  • Recoger los datos. Qué se mide, cada cuánto, con qué instrumento y quién responde por el registro.
  • Analizar. Con el método que admite la naturaleza de esas variables.
  • Interpretar y decidir. Qué se hace con el resultado y con cuánta confianza.

Los cuatro pasos pesan igual sobre el resultado. Un análisis impecable montado sobre datos mal recogidos produce una decisión equivocada con apariencia de rigor, y esa decisión hay que defenderla después ante quien la firma.

Toma el caso que atraviesa el módulo: un área de mantenimiento decide cuándo intervenir una máquina. Antes de que exista una tabla, alguien fijó qué variable representa el desgaste, cada cuánto se lee el instrumento y quién responde por el registro. Cambia una de esas decisiones y cambia la conclusión.

El módulo recorre los cuatro pasos y le da al diseño de la medición el mismo peso que al cálculo.

3 El mapa del módulo

Dieciséis semanas repartidas en tres unidades. Cada una responde una pregunta distinta sobre el mismo caso.

Unidad La pregunta que responde Lo que produce Cierre
1 Qué hay en estos datos Un informe exploratorio con gráficos y resúmenes numéricos 30%
2 Qué tan probable es lo que observo Un modelo de probabilidad ajustado al fenómeno 30%
3 Qué puedo afirmar sobre lo que no medí Conclusiones sobre la población, con su margen de error declarado 40%

Qué hará cada unidad

Unidad 1. Describir lo que hay. Construirás tablas de frecuencia, histogramas, medidas de localización y dispersión, boxplots y gráficos de dispersión. El cierre será un informe exploratorio que muestre qué dicen los datos observados.

Unidad 2. Modelar la incertidumbre. Ajustarás distribuciones de probabilidad y las usarás para calcular la posibilidad de eventos que todavía no ocurrieron. El cierre será un modelo que responda preguntas sobre el fenómeno.

Unidad 3. Inferir sobre el proceso. Construirás intervalos de confianza, pruebas de hipótesis, comparaciones y modelos de regresión. El cierre presentará conclusiones sobre el proceso y declarará el margen de error.

Las tres unidades trabajan sobre un mismo caso. Lo primero es definir el proceso: qué se observa, qué variables lo describen y cómo se registra. Sobre esa definición se monta después el modelo y, al final, la inferencia. El alcance del caso se acuerda en la Semana 02.

TipEl método del módulo

Cada tema pasa por tres momentos:

  1. Concepto. Precisamos qué afirma el resultado y bajo qué supuestos se sostiene.
  2. Implementación. Escribimos el procedimiento en Python y lo ejecutamos sobre datos.
  3. Simulación. Repetimos el procedimiento muchas veces y contrastamos su comportamiento con lo que predice la teoría.

Ese contraste construye criterio. Ves de dónde sale una distribución muestral y mides cada cuánto falla en la práctica un intervalo de confianza.

4 El entorno de trabajo

Todo el módulo se programa en Python. Un análisis que llega sin el código que lo produjo no se puede reproducir ni auditar, y la estadística que no se ejecuta se olvida.

Estas son las piezas y lo que hace cada una.

Librería Qué aporta
pandas Carga los datos y los deja como tabla con columnas con nombre
numpy Cálculo numérico y generación de números aleatorios para simular
openpyxl Es la que permite a pandas leer y escribir .xlsx
matplotlib Motor de los gráficos
seaborn Gráficos estadísticos sobre matplotlib, con menos código
scipy Distribuciones de probabilidad y pruebas de hipótesis
statsmodels Modelos de regresión y ANOVA con la salida que se reporta

Por qué un entorno virtual

Un entorno virtual es una carpeta con una copia aislada de Python y sus librerías. Lo que instalas adentro no toca el Python del sistema ni el de otros proyectos.

Sirve para dos cosas concretas. La primera, que actualizar una librería para otro proyecto no rompa el código de este. La segunda, que fijar las versiones haga que el mismo script produzca el mismo resultado en tu máquina, en la mía y en la de quien revise tu informe dentro de un año.

5 Instalación paso a paso

1 Python

Descarga la versión 3.13 desde python.org/downloads.

En Windows, marca la casilla Add python.exe to PATH en la primera pantalla del instalador. Es fácil pasarla por alto, y sin ella el comando python no funciona en la terminal.

En macOS y Linux el sistema ya trae Python, pero suele ser una versión vieja que además usa el sistema operativo. Comprueba con python3 --version y, si es anterior a 3.11, instala la 3.13 aparte.

2 La carpeta del módulo y el entorno virtual

Crea una carpeta para todo el semestre y ubícate en ella:

mkdir estadistica-analitica
cd estadistica-analitica

Crea el entorno virtual dentro de esa carpeta:

python -m venv .venv

Actívalo. El comando cambia según el sistema:

# Windows, PowerShell
.venv\Scripts\Activate.ps1

# Windows, Git Bash
source .venv/Scripts/activate

# macOS y Linux
source .venv/bin/activate

Cuando queda activo, el nombre (.venv) aparece al comienzo de la línea de la terminal. Si no lo ves, no está activo, y todo lo que instales va a parar a otro lado.

AdvertenciaEl entorno se activa en cada terminal nueva

Cerrar la terminal desactiva el entorno. Al día siguiente, cuando vuelvas a la carpeta, tienes que activarlo otra vez antes de trabajar. Es el tropiezo más común de las primeras semanas.

3 Las librerías

Con el entorno activo, crea un archivo requirements.txt con este contenido:

pandas==2.3.1
numpy==2.3.2
scipy==1.17.0
matplotlib==3.10.8

E instálalas de una vez:

pip install -r requirements.txt

Fijar las versiones con == es lo que hace reproducible el análisis. El archivo se versiona junto con el código: quien reciba tu informe puede recrear el entorno exacto con una sola orden.

Con el entorno activo, ejecuta:

python -c "import pandas, numpy, scipy, matplotlib, seaborn, statsmodels; print('todo listo')"

Si imprime todo listo, ya está. Cualquier otra cosa significa que falta una librería o que el entorno no está activo.

7 Demostración: por qué se mide más de una vez

Esta es la demostración principal de la semana y no hay que entregar nada con ella. La corremos en la sesión y la repites en tu equipo para comprobar que el entorno funciona.

Vamos a medir algo real: cuánto tarda tu computador en ordenar una lista de cien mil números. La operación es idéntica en cada repetición, el tamaño no cambia y la máquina es la misma.

Crea un archivo experimento.py:

import time
import random
import pandas as pd

random.seed(2026)

filas = []
for i in range(1, 201):
    datos = [random.random() for _ in range(100_000)]
    inicio = time.perf_counter()
    datos.sort()
    fin = time.perf_counter()
    filas.append({
        "medicion": i,
        "tiempo_ms": round((fin - inicio) * 1000, 3),
        "tamano": 100_000,
    })

mediciones = pd.DataFrame(filas)
mediciones.to_csv("tiempos_ordenamiento.csv", index=False)

print(mediciones.head())
print()
print(mediciones["tiempo_ms"].describe())

Ejecútalo con python experimento.py. Tarda alrededor de un minuto.

Qué acaba de pasar

Doscientas repeticiones de la misma operación, y ni una sola coincide con otra. La más rápida tardó 15.8 milisegundos y la más lenta 38.6: la más lenta se demoró más del doble que la más rápida.

Tus números van a ser distintos a estos, y eso también es parte del punto.

La causa no es el azar puro. El sistema operativo reparte el procesador entre muchos procesos, la memoria caché a veces tiene los datos a la mano y a veces no, y otros programas compiten por el equipo. Ninguno de esos factores se puede controlar por completo desde el programa.

Fíjate en el random.seed(2026) de la tercera línea. Fija la secuencia de números aleatorios que se generan, así que la lista que se ordena es siempre la misma. Aun controlando eso, los tiempos varían. La variabilidad no viene de los datos: viene de la medición.

De ahí sale la pregunta que ordena el módulo entero: si cada medición da distinto, ¿cuál es el valor verdadero? Para responderla, separa cuatro ideas:

  • La población es el conjunto completo de resultados que podría producir el proceso. En este experimento incluye todos los tiempos que obtendrías al repetir la operación bajo condiciones comparables.
  • La muestra contiene los resultados que sí observaste: las 200 mediciones.
  • Un parámetro resume una propiedad de la población, como su media. Permanece desconocido porque no puedes observar todos los resultados posibles.
  • Un estadístico es un número calculado con la muestra. La media de 22.6 milisegundos es un estadístico y funciona como estimación del parámetro.

Esa flecha punteada es la Unidad 3. Las unidades 1 y 2 construyen lo que hace falta para poder trazarla con honestidad: describir la muestra y modelar la variabilidad.

ImportanteLa consecuencia práctica

Un solo dato no es evidencia. Si alguien reporta que una máquina se demoró 38 minutos en una intervención, no sabes si es la máquina o es el ruido de una sola medición. Toda la discusión de este semestre nace ahí.

8 Los tres formatos de almacenamiento

El módulo organiza la información en tres formatos de almacenamiento. Cada uno tiene su lugar.

Formato Qué es Cuándo lo vas a usar
.csv Texto plano, valores separados por comas El formato por omisión. Lo lee cualquier herramienta y ocupa poco
.txt Texto plano con otro separador, casi siempre tabulación Lo que exportan muchos equipos de medición y sistemas industriales
.xlsx Libro de Excel Cuando el dato llega de un área que trabaja en Excel, o cuando el informe se entrega ahí

Descarga el archivo de ejemplo, ordenes.csv, que tiene 12 órdenes de mantenimiento. Guárdalo en tu carpeta de trabajo.

Crea formatos.py:

import pandas as pd

ordenes = pd.read_csv("ordenes.csv")

ordenes.to_csv("ordenes_copia.csv", index=False)
ordenes.to_csv("ordenes.txt", sep="\t", index=False)
ordenes.to_excel("ordenes.xlsx", index=False)

desde_csv = pd.read_csv("ordenes_copia.csv")
desde_txt = pd.read_csv("ordenes.txt", sep="\t")
desde_xlsx = pd.read_excel("ordenes.xlsx")

print("csv  y txt :", desde_csv.equals(desde_txt))
print("csv  y xlsx:", desde_csv.equals(desde_xlsx))
print()
print(desde_csv.head())
print()
print(desde_csv.dtypes)

Los tres archivos guardan exactamente lo mismo. El index=False evita que pandas agregue una columna extra con la numeración de las filas, que no es un dato y ensucia el archivo.

Anatomía de una tabla de datos

Esa tabla tiene una estructura que se repite en todo el semestre:

  • La unidad de observación es lo que ocupa cada fila. Aquí, una orden de mantenimiento.
  • Cada variable es una columna: algo que se midió u observó de esa unidad.
  • Cada registro es una fila completa: todos los valores medidos de una misma unidad.

Mira la última salida. Pandas leyó duracion_min como float64 y repuestos como int64, y acertó en ambos. Pero puso object en maquina, turno, tipo y criticidad, que es como decir “texto y no sé nada más”. Ahí perdió información: criticidad tiene un orden natural, baja va antes que media y media antes que alta, y esa tabla no lo registra.

Quédate con la idea, porque la semana 2 arranca justo ahí: la naturaleza de una variable la declaras tú, no la adivina la herramienta, y de esa declaración depende qué análisis puedes hacer después.

11 Errores frecuentes

Error 1

ModuleNotFoundError: No module named ‘pandas’

Causa. El entorno virtual no está activo, o instalaste las librerías sin activarlo.

Solución. Mira el comienzo de la línea de la terminal. Si no dice (.venv), actívalo con el comando de tu sistema y vuelve a intentar. Si ya está activo, ejecuta pip install -r requirements.txt otra vez: la primera vez fue a parar al Python del sistema.

Error 2

ModuleNotFoundError: No module named ‘openpyxl’ al guardar el .xlsx

Causa. Pandas no escribe Excel por su cuenta: necesita openpyxl y lo importa solo cuando lo usas. Por eso el error aparece en la línea del to_excel y no al comienzo.

Solución. pip install openpyxl==3.1.5, con el entorno activo.

Error 3

FileNotFoundError: ordenes.csv

Causa. La terminal no está parada en la carpeta donde guardaste el archivo. Python busca los archivos desde el directorio actual, no desde donde está el script.

Solución. Ejecuta pwd en macOS y Linux, o cd sin argumentos en PowerShell, para ver dónde estás. Muévete a la carpeta correcta con cd y vuelve a ejecutar.

Error 4

Al abrir el .csv, Excel mete todo en una sola columna

Causa. Excel en español espera punto y coma como separador, no coma.

Solución. No abras el .csv con doble clic. Usa el .xlsx que generaste, que es justo para eso. Si necesitas el .csv en Excel, ábrelo desde Datos, Obtener datos, Desde un archivo de texto y elige la coma como separador.

No cambies el separador del archivo: la coma es el estándar y el resto del semestre asume que la tiene.
